# Callable lexical source context95, separate from canonical ownership

Hypothesis: exclusive source ownership answers who owns a line, but loses nested
implementation when used as the complete context of the outer callable. Three
already inspected development witnesses show this information loss; their hand
windows are feasibility examples, never a selection rule or measured improvement.

First build a source-only, versioned callable context catalog for every source
file in the16development scopes, before query-specific selection or labels.
Keep canonical source7Passages/EntityKeys/ordinals/owned_regions and old profiles
unchanged. Reuse current grammars and AST byte ancestry. One context has a primary
canonical callable and faithful physical source parts with their original
canonical owners. Record source SHA, index/profile generation, actual bytes,
syntax scope boundaries and nesting. Containment asserts no execution, resolved
call/return, reachability or runtime ordering. No54/54bcallee targets.

Require fresh canonical partition/extent equality, exact physical bytes and
unambiguous AST binding. Invalid syntax, ambiguous line-only identity or partial
same-line scopes produce explicit diagnostics and no authorization. Anonymous
callbacks do not acquire invented function identities; representing independent
anonymous fragment units would be a separate design. No sibling/import/call
expansion, name guesses, min/max envelopes or reparented Passage entities.

The first slice is only this source context abstraction, synthetic public-usage
TDD and an independent source provenance review. No queries, model inference,
fits, ranking change, visible evidence change or quality result belong to that
slice. Whole-repository source metadata and physical/provenance hashes must be
reviewed before any subsequent projection/presentation/ranking experiment.

A future experiment must preregister one fixed projection/selection policy and
new profile/evidence version, use the same context authorization in capacity,
projection and visible presentation, and independently review fresh target
construction. Historical targets and responses remain immutable. Original
references, ALL400 denominator, exact identity/ordinal, ALL anchors of one
original alternative, CPU,3fragments/40visiblelines/12000finalJSONchars and the
+5strict gate remain unchanged. Provenance metadata consumes the final budget;
after trimming, removed source remains absent for scoring. Prepared source
coverage is neither a correct answer nor90%acceptance.
