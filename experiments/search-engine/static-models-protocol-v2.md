The v13 baseline exposed an actual batch-composition defect: Potion-code's serialized tokenizer enables longest-batch padding and a hidden512-token truncation, while Model2Vec pools all returned ids and does not clear those settings. Equal text hashes therefore did not imply equal vectors. Native other controls have padding=None; amgix also carries a32768 tokenizer truncation. Fix the registered adapter by clearing padding and tokenizer truncation before counting/encoding. Model2Vec's explicit encode max_length512 remains; full budget counting sees all tokens. Bind this policy into a new revision. Source-only witness and regression precede corrected scores.

Run the seven registered models under this policy, one at a time in CPU-only fresh preparation/measurement processes. Keep native table dtype/dimension, mean/L2, and no remote code. In that case clearing those settings is exactly a no-op.
