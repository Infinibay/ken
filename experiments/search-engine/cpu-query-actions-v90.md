# Query actions90: distinguish requested operations from surrounding topic words

Research-only proposal after negative source relation unions/clauses51/57,
within-file owner62 and linear88b. No new fitted90 model or default promotion.
The original251 features treat all query content words together. A factory's
explanatory docs and its callable's executed behavior can share the topic while
only one contains the requested operation. Test whether grammatical query
predicates add information rather than another source cosine.

Register one English averaged-perceptron POS model from official NLTK data
(JSON, MIT), pinned package hashes and nltk3.9.2. CPU-only, no transformer,
GPU/generator/external inference. Measure its actual cold/warm RAM/time before
considering runtime adoption. Use existing expanded query/translation cache,
not new translations or rewritten requests; raw251 features stay unchanged.

Treebank tokenization of the expanded query, then frozen POS tags. Preserve in
original order tokens tagged VB/VBD/VBG/VBN/VBP/VBZ except generic auxiliaries:
am,is,are,was,were,be,being,been,have,has,had,having,do,does,did,doing.
No benchmark identifier, source name, gold reference, synonym alias or query-ID
rule. This is grammatical evidence, not a proven semantic parser. Keep original
query negation/literals/conditionals in the251 base, never reinterpret them as
hard filters. Missing actions produce explicit zeros and presence/count metadata.

Same existing Potion static encoder, code_terms/stemmer/TermAlignment formulas,
source7 owner descriptions and fields. Additional action-only coverage on
executable/calls/returns (three10-feature blocks), plus action_present,
log_action_tokens,action_token_fraction:33extra columns,284total. No new source
projection, corpus, embedding weights or context-vector recoding. Empty-action
rows are allzero. Root will first audit POS outputs/time/size as diagnostics;
no quality or acceptance claim from tagging accuracy alone.

If preparation supports the hypothesis, one fixed existing160tree/15leaf/
min_child40/lambda2/lr.08/seed42 LambdaRank parent69 control,16whole-repo excluded
folds, sameoriginal eligibility/source/candidate pools, exactauthority,
evidence3 and full400/strata/ALLanchors/10/40/12000 budgets. No HPO/synonym sweep,
held fitting, dropout of no-action/Spanish cases, reserve access or external
query/code transmission. Existing+5strict integration gate and90% acceptance
unchanged. Bind source/model/query inputs and review exact controller before fit.
