# External code-retrieval benchmarks

Research date: 2026-10-16. No new external accuracy result is claimed here.
Our 400 exposed queries (240 English) are development, not independent acceptance.
The sealed reserve remains closed, including its public queries.

## Evaluation responsibilities

A transport adapter translates returned identities and locations without changing
queries, corpus, references, rank slots, candidate counts or failure outcomes.
A scorer owns the original benchmark's relevance definition. An additional
piece-identity metric must have an independently specified target, rather than
equating a relevant file with a correct function or class.

| Benchmark | Source and task | Role for Ken | Limits |
| --- | --- | --- | --- |
| RepoQA SNF | https://github.com/evalplus/repoqa — 500 cases, 50 repositories, 5 languages; function descriptions omit target names. | Evaluate returned function identity and first relevant rank in a pinned repository. | The original is an LLM long-context task with generated descriptions and a syntactic similarity scorer. A retrieval adapter is a named variant, not the original official LLM score. Check repository/context reconstruction and valid alternatives before measuring. |
| CoIR | https://github.com/CoIR-team/coir — ten datasets, eight retrieval tasks and a BEIR/MTEB-compatible harness. | External retrieval comparison, original task metrics plus clearly named Hit@1/10 when justified. | It aggregates heterogeneous tasks; not all represent repository navigation, and it is not interchangeable with Semble's own benchmark. |
| CodeSearchNet Challenge | https://github.com/github/CodeSearchNet — 99 general queries with human relevance judgments across six languages. | Classic external graded-relevance test. | Distinguish the human challenge judgments from the much larger scraped docstring–function dataset. Incomplete pooled judgments do not certify every unjudged result irrelevant. The original challenge has concluded. |
| CORE-Bench | https://github.com/zhangfw123/CORE-Bench-Eval and https://huggingface.co/datasets/zhangfw123/CORE-Bench — code understanding, issue-to-edit localization and broader repository context retrieval. | Particularly relevant external task model for coding-agent retrieval; evaluate Level 2 and Level 3 separately. | Recent benchmark, not a universal established standard. Packaged documents have their own identities/chunks; verify source/revision reconstruction and annotation provenance before calling results native repository search. The package excludes Level 1. |
| Loc-Bench | https://github.com/gersteinlab/LocAgent — repository issue localization. | Complementary file/module/function localization from real development issues. | Multiple modified locations require coverage metrics; any-hit top10 is different from all-targets top10. Edited code is not necessarily the full supporting context. |

Recommended order: preserve the existing Semble comparison on the same pin;
use RepoQA for an independently defined target function; then evaluate
CORE-Bench's localization and supporting-context tracks separately. Do not tune
on a repeatedly inspected test set and subsequently call it unseen acceptance.
Do not train on external test labels. Check overlap by repository and revision
with development and any external model adaptation data; disclose overlap and
unknown pretraining exposure.

## Semble comparison boundary

Current Semble README advertises 0.855 NDCG@10 over roughly 1,250 queries in
63 repositories and 19 languages. Its methodology says queries and relevance
labels are generated by Claude Sonnet 4.6, which also verifies labels:
https://github.com/MinishLab/semble/blob/main/benchmarks/README.md

Our historical local pin is 0e5e02832ae0340c0feb637d2b7213fe065571fd,
Semble 0.6.2, 1,251 queries. The closed V76b review records 1,217 queries
with file-only relevance and 34 with some line-range relevance. Consequently,
adapting response format alone cannot turn that corpus into strict function or
class identity labels. Keep the original NDCG and call its binary derived
metrics annotated-target Hit@1/10, not strict correct-function accuracy.

Preserve macro-repository and micro-query aggregates explicitly; the current
README describes a query average. Never compare an older macro score directly
to a newer micro score without pinning the data and scorer. Run Ken and Semble
against identical requests and source revisions, record every missing/error
response as a failure, and report actual API output and native retrieval
separately if output budgets reduce the number of visible candidates.

## README claims

Publish exact numerator/denominator, benchmark revision, engine version,
configuration, hardware, query languages, original metric definition, derived
metric definition, uncertainty and reproduction commands. Distinguish warmed
retrieval from process startup and indexing; measure complete CPU latency,
whole-process peak RAM and returned token budgets. Show per-track and per-kind
results before aggregating. Comparison quality, latency and token savings need
their own matched protocols. A development 90% does not support a general
"90% accurate" headline or an external benchmark result.
