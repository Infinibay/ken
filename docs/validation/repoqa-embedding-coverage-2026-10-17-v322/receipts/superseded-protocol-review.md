# Independent protocol review — V320/V321

Static review only, before quality inspection. No response/raw result files, private reserve, model execution, grades, or producer edits were used. Findings refer to the reviewed producer versions; subsequent corrections require separate verification.

1. **Required / P1 — Muninn pooling does not match the native artifact.** `output/models/muninn-small-v319/5868553640ac37d851fa813b4e27f85a8630cea1/modules.json` selects the `1_Pooling` SentenceTransformer module, whose `config.json` explicitly declares `"pooling_mode": "cls"` and `"include_prompt": true`. The model README recommends `SentenceTransformer(...).encode(..., prompt_name=...)`. In contrast, `v321/export.py:11–14` computes attention-mask mean. Its parity check at lines 22–23 compares ONNX against that same custom mean wrapper, so passing it establishes export fidelity but cannot establish native embedding fidelity. This would benchmark a modified Muninn encoder while calling it native. **Remedy:** before candidate capture or any quality inspection, record a protocol correction to official CLS pooling, export it, and compare against the official SentenceTransformer pipeline with the registered prompts, normalization, and token budget. Include the raw `Tokenizer.from_file` path used by capture in the parity check, since the current check supplies both backends with the same AutoTokenizer IDs. Retain any superseded artifact distinctly; do not select pooling from benchmark scores. The 384→768 zero padding itself preserves cosine and is not the problem.

2. **Required / P2 — A closure file does not prove the all-600-successful-calls grading gate.** `v320/capture.py:75–82` and `v321/capture.py:54–61` record worker failure, continue, and finally publish `all_outputs_closed=True` with hard-coded query counts even when a worker failed. `v320/grade.py:18` checks only that V321 closure exists. `v321/grade.py:14–22` checks closure metadata and pins, then runs the control grader before validating candidate failure markers, provenance, and request IDs at lines 27–30. Consequently a failed candidate worker can allow control quality grades to be written before all 600 calls succeeded. **Remedy:** add a label-free preflight, before either grader reads references or calculates ranks, verifying all 60 workers succeeded, every expected response/raw ID occurs exactly once, all provenance is complete, and closure pins match. Distinguish closed/failed captures from successfully complete captures. This is a conditional integrity defect, not evidence that a current worker has failed.

3. **Required / P2 for reporting — Final-stage `top100` is not measured.** Both graders set `top100` from whatever list they receive (`v320/grade.py:44–46`, `v321/grade.py:38–39`), but the public API is explicitly called with `limit=10` (`v320/capture.py:149`, `v321/capture.py:128`). Thus final-stage `top100` is necessarily identical to final-stage `top10`, and cannot support a claim about the final ranker's top-100 candidate recall. **Remedy:** omit or mark final-stage `top100` unavailable; keep actual contextual top-100 results separate. No recapture is needed for the registered top-1/top-10 question.

4. **Required / P2 for cost claims — The control report's “Jina is cold” label is inaccurate.** `v320/grade.py:48` describes preparation as reused CodeRank versus cold Jina. However `v320/capture.py:44–59` merges both existing baseline and Jina source caches from V318 into the V320 input cache whenever present. The supplied preparation-equivalence record confirms earlier Jina workers existed. **Remedy:** report actual per-worker `prefill.json` new/reused counts and describe preparation as mixed cache state. Do not compare these totals as cold indexing costs. Likewise retain the existing qualification that peak process RSS includes four-call source preparation; it is not steady-state warm-query RAM or the native 384-dimensional storage cost.

5. **FYI — Scope of inference remains limited even after these corrections.** Equal 512-token budgets use different tokenizers/prompts; Muninn FP32 and the INT8 models also differ in architecture, dimensions, precision, and training. This experiment measures those fixed artifacts as replacements under Ken's existing forests and Ettin, not the isolated causal benefit of C++/Rust training coverage. The token audit counts original queries and gold source views (`v321/audit_tokens.py:22–39`), not expanded queries or the complete corpus, so it cannot establish that every embedding input fits. Keep the registered RRF60/top100 combinations exploratory and distinct from actual API results; the top-10 union is only an oracle bound with more than ten slots. With 200 exposed English queries nested in 20 repositories, report paired gains/losses and repository/language variation; any uncertainty estimates should preserve repository clustering. Do not claim blind generalization, official RepoQA SNF performance, or production promotion from this experiment.
