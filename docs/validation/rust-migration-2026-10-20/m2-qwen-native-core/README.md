# Native Qwen3 core proof

This records production C ABI execution with the exact registered Qwen3 embedding and reranker weights through an independently linked Rust host. CPU runs on macOS and Linux for F32, F16 and BF16; MPS runs on actual Apple hardware for all three precisions. Original input IDs/masks and normalized-vector or raw yes/no outputs are compared with the frozen original corpus. Expected outputs never enter the Rust process. The original-derived deadlines and vector1e-6/raw1e-5 bounds are unchanged.

Each group retains inputs, raw outputs, actual runtime/device identity, mapped-library diagnostics, source hashes and measured timings. Linux also retains one-executable strace records. macOS dynamic-loader diagnostics do not constitute a kernel child-exec audit. Temporary model/core files are privately owned, with process scratch held under the parent's owned temporary directory. Native dependency paths are relative; production runs remove test-only loader paths.

Earlier Linux attempts exceeded the original-derived BF16 or F16 deadlines. Their failure logs are preserved. A paired 32-token diagnostic measured original/native forward times of 4.920/4.860 seconds with the same 196 matrix multiplications and 28 CPU flash-attention calls. A separate paired hashing benchmark demonstrated a faster equivalent SHA-256 implementation. Commit 4047338245a0b99f9a237bb415f214f677ce0fa8 switched bounded artifact verification to the already locked Ring digest implementation, with all 160 model contracts passing on each platform. A later bounded F16 diagnostic completed in 31.095 seconds, including 2.613 seconds of artifact verification and 3.755 seconds of native preparation. Environmental variability prevents attributing the entire timing change to hashing. All accepted full groups use the new identical source map and retain the original deadlines and numeric bounds.

An actual execveat negative control exposed a gap in the previous execve-only Linux trace filter. Both syscall filters are now enabled and verified using a healthy control and an actual execveat control. Every accepted Linux profile has a fresh trace and a source/artifact receipt; previous successful numerical profiles are historical evidence only.

This is core acceptance only. Text/token/prompt/device-state adapters, explicit untied-head policy, MLX, acquisition/integration and remaining migration stages are still required. The original application sources are preserved.
