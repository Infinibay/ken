# Native relational and vector storage implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans inline, task-by-task. Preserve native execution; no implementer agents, one fresh final reviewer. Steps use checkbox syntax.

**Goal:** Read/write existing project data natively with demonstrated slot integrity, cross-language compatibility and process-crash recovery.
**Architecture:** ken-store owns SQLite/slots/segments and maintenance; the SQL resource stays shared. A ProjectStore coordinates recovery before exposing a project. Models supply decisions explicitly and keep their existing owner.
**Tech Stack:** Rust1.95, existing rusqlite0.40.2/bundled, serde/serde_json/thiserror/tempfile/libc/ndarray/sha2 workspace versions; no new inference runtime or persistent format.
**Spec:** docs/superpowers/specs/2026-10-19-rust-storage-design.md

## Global Constraints

- Preserve all1066 originals, user indexes, installed entrypoints and unrelated work.
- Native inline continuous execution; finish the current policy acceptance before implementing this plan. No new stage-confirmation pauses.
- Format1/F32/little-endian/65536rows per default segment; existing SQLite schema and all3 vector-space names unchanged.
- WAL/synchronous=NORMAL/foreign_keys=ON/busy_timeout=5000ms; allocator requires BEGIN IMMEDIATE.
- Numeric comparison abs1e-6+rel1e-6, fixed before native implementation; exact IDs/slots/dimensions/order/metadata effects and exact bytes where arithmetically exact.
- Corrected integrity cases are separate from identical original behavior; unknown/unreadable is never proven empty.
- No reader-serializability, power-loss, model-backend or installed-promotion claim.
- All prior28 gates plus storage_release/storage_parity/storage_recovery=31,29current fingerprints and BOTH registered platforms. M2_accepted=false.
- Preserve runtime deadlines, baseline IDs/typing, original hashes, prior fixtures and zero missing-model skips.

## Review Focus

1. Model metadata present-empty/NULL and physical empty BLOB/zero/negative slots must not permit accidental repinning; storage read errors must not become empty facts.
2. Reused slots, cascade deletion, two writers and rolled-back vector writes must never create duplicate ownership or committed references to unwritten bytes.
3. Segment creation races, truncation, repeated slots, NaN/Inf/norm overflow and invalid manifests must fail safely without resizing mapped files or publishing false zeros.
4. A kill between journal publication, either rename and SQLite commit must recover a complete old/new mapping; journal paths must not identify unrelated files and cleanup must be idempotent.
5. The composed receipt must bind the full current/nested raw proof and fresh binaries, reject altered/missing artifacts and execute outside the checkout without Python.

## Public interfaces and ownership map

Create `crates/ken-store` with modules `database`, `schema`, `transaction`, `slots`, `model_state`, `manifest`, `segments`, `vectors`, `maintenance`, `recovery`, `project` and `error`. Split maintenance by migration/compaction only when working examples require it; do not create empty future modules. Tests live under the same crate's `tests/`; examples are validation drivers, not user CLI promotion.

`StoreResult<T>=Result<T,StoreError>`; errors identify Sqlite/Io/CorruptManifest/Dimension/InvalidSlot/NonFinite/Recovery/UnknownSpace and preserve source/path context. No success-shaped empty results for failed I/O.

- `ProjectDatabase::open(path:&Path)->StoreResult<Self>`, `initialize(&mut self)->StoreResult<()>`, `connection(&self)->&rusqlite::Connection`, `get_meta(&self,key:&str)->StoreResult<Option<String>>`, `set_meta(&self,key:&str,value:&str)->StoreResult<()>`, `immediate(&mut self)->StoreResult<WriteTransaction<'_>>`, `model_state(&self)->StoreResult<StoredModelState>`.
- `WriteTransaction<'a>` owns the actual rusqlite immediate transaction; `connection(&self)->&Connection`, `commit(self)->StoreResult<()>`; Drop rolls back. Helpers accept this same transaction instead of reopening nested transactions. `model_state(&self)` uses the same authoritative query helper; `pin_model_if_fresh(&mut self,model:&str,document_space:u32)->StoreResult<bool>` rechecks NULL/absent marker+no file vectors and writes both metadata keys only if fresh.
- `StoredModelState{recorded_model:Option<String>,file_vectors_present:bool}` is physical facts, not selection policy. Empty string remains Some(""); NULL/absent remains None.
- `VectorSpace::{Files,Symbols,IntentSources}` maps only to ci_files/ci_symbols/ci_intent_sources; FromStr rejects all other names. `allocate(tx:&mut WriteTransaction,space:VectorSpace,count:usize)->StoreResult<Vec<i64>>`, `release(tx:&mut WriteTransaction,space,slots:&[i64])->StoreResult<()>`, `high_water(conn:&Connection,space)->StoreResult<i64>`.
- `VectorStore::open(directory:&Path,space:VectorSpace,dim:usize,model:Option<&str>)->StoreResult<Self>`, `write(&self,slots:&[i64],vectors:&[Vec<f32>],durable:bool)->StoreResult<()>`, `read(&self,slots:&[i64])->StoreResult<Vec<Vec<f32>>>`, `scores(&self,query:&[f32],count:usize)->StoreResult<Vec<f32>>`, `flush(&self)->StoreResult<()>`, `bytes_on_disk(&self)->StoreResult<u64>`. Empty slots/count preserve original early-return semantics. Row vectors own their values.
- `verify(conn:&Connection,store:&VectorStore)->StoreResult<VerificationReport>` preserves the seven named integer fields. `live_scores(conn:&Connection,store:&VectorStore,query:&[f32])->StoreResult<Option<LiveScores>>`, `LiveScores{slots:Vec<i64>,scores:Vec<f32>}` removes free slots, preserving order. Unavailable empty high-water yields None; I/O/dimension failures stay errors for the application adapter to decide fallback.
- `ProjectStore::open(paths:&ken_core::project::ProjectPaths)->StoreResult<Self>` creates only the explicit data directory if needed and recovers pending native compaction before exposing data. It owns paths/database; `database()/database_mut()`, `initialize()`, `vectors(space,dim,model)` are the representative caller surface. ken-core does not depend on ken-store and its status reader stays read-only.
- `migrate_inline(project:&mut ProjectStore,dim:usize,model:Option<&str>,batch:usize,progress:impl FnMut(MaintenanceEvent))->StoreResult<BTreeMap<VectorSpace,u64>>`; positive batch, default2000 chosen by caller. `compact(project:&mut ProjectStore,dim,progress)->StoreResult<BTreeMap<VectorSpace,CompactionCount>>`, `CompactionCount{before:i64,after:i64}`. `reclaim_database(db:&mut ProjectDatabase)->StoreResult<(u64,u64)>` performs VACUUM/checkpoint outside a transaction and reports errors to the caller.
- `MaintenanceEvent` carries space/count progress and publication phases StagingReady/JournalPublished/BackupRenamed/NewPublished/DatabaseCommitted/Cleaned. A callback is ordinary progress/diagnostics; the test driver can block it using pipes. No product failure flag, panic hook or environment failpoint.
