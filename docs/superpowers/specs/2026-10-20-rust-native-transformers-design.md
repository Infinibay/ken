## Concepts and responsibilities

- Transformer registration: owns exact data artifacts, immutable revision, architecture/weight layout, tokenizer/pooling modules, prompt rules and supported configuration. ModelAssets/ModelFileSource/VerifiedModelFiles remain authoritative for file identity and independent ownership.
- Transformer tokens: reproduces the actual ST or MLX preprocessing and tokenizer pipeline. Count without specials stays untruncated and independent of model loading for local profiles. Owns right padding, truncation and restoration. ST5.6.1 sorts by Unicode character count using NumPy2.4.4 default argsort (including its tie behavior); MLX explicitly stably sorts token lengths. Do not replace one with the other or presume argsort stability.
- Transformer core: owns the architecture and loaded weights; returns the requested pooled tensor or raw projection. Qwen3 owns attention/RMS/RoPE/MLP/residuals; XLM-R owns embedding positions/LayerNorm/attention/GELU/residuals. No request retains causal KV state.
- Native backend module: owns the real tensor library and device operations. Torch and MLX implement the same narrow native API through separate Rust dynamic libraries; neither depends on Python.
- Native transformer session: lazily verifies/maps a backend, retains the native library/model handle and its independent model files, serializes actual requests and reports real runtime/device state. Drop destroys model handles before library/file owners. Failed initialization leaves no published partial state and permits repair/retry.
- Sentence encoder: owns ST model/tokenizer lazy states, declared module pooling/normalization, prompts and permanent CPU demotion only after successful rebuilding. Dimension loads the model; an empty batch does not. GPU invalid/failed vectors retry on CPU, CPU failures propagate.
- MLX encoder: owns Qwen-only validation, stable length batches, last-real selection, F32 normalization and min(previous,512MiB) free-cache bound. Never raises live-weight/host limits. MLX errors propagate.
- Relevance judge: owns PREFIX/SUFFIX/instructions, query128, minimum source16, full budget accounting and raw F32 yes-minus-no projection. Loads/checks budgets even for empty documents, preserves batch order, retries other failed devices once on CPU/F32 while CPU/MLX errors propagate.
- Equivalence receipt: authenticates source, model, runtime, device, actual requests/results, dependency/exec audits and exact regression coverage. Compatible legacy profile identity is distinct from native runtime evidence.

## Optional-library boundary and alternatives

Choose lazy native Rust backend modules through a small versioned C ABI, following the existing verified NativeOnnxRuntime lifetime pattern. A normal CLI/status invocation must work without optional Torch/MLX dependencies: it does not map their module until that backend is used. The host does not link tch or MLX and cannot accidentally load their cores during project inspection. Backend crates build independently from the default workspace; model/data/API crates remain shared and light. Packaging M8 must include verified modules, cores and shaders with relocatable loader paths.

Compared alternatives: linking tch/MLX directly into ken-models makes optional cores mandatory at process startup; a persistent native subprocess isolates cores but adds a second lifetime/pipe/deadline protocol and startup overhead. A lazy C ABI preserves the existing in-process tensor lifetime and optional dependency behavior. Cost: unsafe FFI must be small, versioned, bounded and tested; a model/native library must never be unmapped while a handle/output exists.

The ABI transports bounded versioned requests/results and backend-owned buffers with an explicit release function. No Rust collection/layout or trait object crosses the boundary. Host copies/authenticates outputs before releasing their buffer. Every exported function catches Rust panics and returns a bounded diagnostic; tensor/C++ failures use fallible APIs. Null/length/version checks precede slice construction. A model handle may move between threads only under serialized ownership; each backend proves its model state Send and uses thread-local streams per call. The host retains an Arc owner of the mapped module until every model/output is destroyed. A backend describes actual core version/devices only after real native inspection.

## Exact interfaces and safety limits

The plan defines `TransformerDtype::{Float32,Float16,BFloat16}`, `TransformerDevice::{Cpu,Mps,Cuda(usize)}` and settings with optional dtype/sequence/batch, plus native observed identity separately from legacy profile identity. Existing `ModelAssets`, `ModelFileSource` and `VerifiedModelFiles` own source verification and independent copies; no alternative artifact cache is introduced. `SentenceEncoder`, `MLXEncoder` and `RelevanceJudge` own their distinct public policy. No Rust EncoderSpec/RetrievalProfile exists yet; their identity integration is later work and cannot be simulated by fabricated package installation.

The native ABI is `ken_model_api_v1`, repr(C), version1 with exact struct size and backend identifier. It has bounded byte spans, integer registry handles, explicit open/run/close/release, and status codes. Requests/results are at most16MiB and diagnostics64KiB; positive lengths require non-null valid buffers. The unsafe ABI caller must provide readable/writable, correctly aligned live memory for the stated span; arbitrary forged addresses cannot be made safe by a null check. Production host callers construct those spans from owned Rust slices. Unknown/stale handles never become pointers. Backend-owned results are copied before explicit release; a module owner outlives all model/result owners. All exported operations catch Rust unwind, return fallible native errors, and never manufacture success from a partial allocation.

Use shared typed serde request/result structs with deny_unknown_fields; do not expose Rust collection layout over FFI. A request names a registered architecture/layout, dtype/device, owned model path, validated config and output policy. Model state is Send and serialized; MLX streams remain thread local per invocation. A caller cannot change model/core registration after a session is ready. No optional Torch/MLX library is linked into ordinary ken-cli startup.
